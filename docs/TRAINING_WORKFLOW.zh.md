# 训练工作流

官方手册已按固定 commit 保存并注明来源；[本仓库规则](../AGENTS.md)选取了适用部分，
增加 HD-1910 适配及用户要求的视频、全过程头颈接触检查。不会把手册推荐的轮数当作一定成功的承诺。

1. 检查官方更新，记录依赖、扩展源码、参数和模型 hash。先复核机器与进程状态。
2. 验证物理目标：带噪声站姿/坐姿各固定控制至少3秒，报告倾角、稳定后高度、支撑和头颈间隙。
   `scripts/pose_preflight.py` 是 CPU 诊断工具。它不运行学习策略，也不证明过渡动作可行。
3. 奖励审查：真实函数符号、量纲、加权贡献，以及保持不动/正常进展/躺倒/借头支撑的收益。
   成功条件须独立于密集奖励；失败锁存不能由最终坐稳清掉。
4. 配置测试和 64×5 烟雾检查：构建、NaN、actor 61D、全部奖励、ONNX导出及归一化对照。
5. 有界小试：从已验证初态开始，先单方向后双方向。每100–200轮确定性评测动作进展、头颈接触与实际奖励。
   没有进展就检查原因，不以继续加罚或自动追加长训代替诊断。
6. 仅在小试两方向有安全进展后扩大初态/扰动/环境数。所有前置证据和训练身份应绑定，修改物理或目标后重做。
7. 候选在匹配运行时与独立CPU环境评估。提供完整视频和失败样例；自动通过后仍待用户人工核验。

旧 `acceptance.py` 的姿态结果缺少子步头颈证据。现已加必需字段，旧报告重新评判只能未验证或失败；
不能仅补一个人为写入的0来放行。完整接触数据应来自独立审计，不能用控制帧抽样替代物理子步。
旧 ACCEPTED 字样只表示当年的旧指标结论，不构成上机授权。

解剖部位按编译模型核验：头颈为 `neck` 完整子树；官方历史DR兼容列表中的
`bearing_roll` 实际是右髋。历史将其并入头部的最小间隙是保守superset指标，
不能称纯头颈间隙。新审计分别输出真实头颈、右髋与历史superset，合法坐姿另要求非足承重。

## 坐姿冷启动与目标延迟历史

`sim2sim.py` 默认 `--cold-start measured`：直接从带噪坐姿放入仿真时，延迟队列先保持测得的位置，
再按原延迟收到策略的第一条实际目标。不能在没有此前HOME运动的情况下，隐含预装HOME目标。
`--cold-start first` 用第一条经过目标处理的策略指令填充历史，作为首值填充对照；
`--cold-start home` 显式保留旧HOME冷历史，作为单独的稳健性压力测试。三者都会写入结果，
不会重评或覆盖旧失败；旧报告没有记录此字段时标为未记录。

孤立GPU DelayBuffer同样会回填首次append，但完整 `ManagerBasedRlEnv.reset()` 在返回观测前
先执行 `scene.write_data_to_sim()` 和 `sim.forward()`；前者也会触发延迟处理和执行器计算。
因此first不能直接代表某次现存训练的完整冷启动。验证时要追踪最终姿态写入之后、第一条策略
动作之前实际进入缓存的目标、平滑器、力矩和电压状态；不能一律要求pending为真、历史和力矩为零。
部分环境重置后的全场景刷新也须检查对未重置环境的影响。

原生飞特启用扭矩前先读取并预装当前signed raw位置；另有显式home ramp和运行中的历史继承。
这里的measured是连续角度近似，没有逐位模拟原生编码器量化、turn和采样时刻；first也不代表
CPU/GPU全部物理一致。正常运行中的策略切换应保留真实历史，不能用任一种冷启动替代。
目标平滑器仍从测位开始，延迟分布、采样次数、后续命令延迟以及策略previous-action语义不变。
坐姿启动改善后，仍须分别检查站起、坐回及全过程头颈接触；改善单个起点不等于模型合格。
